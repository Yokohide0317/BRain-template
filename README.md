# BRain-template

Markdown で知識と作業記録を整理するための空の保管庫です。Obsidian は任意です。領域（scope）ごとに資料、知識、修正経験、ルールを分け、AI が見つけた「学び」は候補として残します。候補は人が確認するまで指示になりません。

## 使い始める

1. このフォルダを自分の作業場所にコピーします。Obsidian を使う場合は、このフォルダを保管庫として開きます。
2. `Memory/scopes/` にある架空の例を読み、自分の領域名で新しいフォルダを作ります。領域名は短い英数字とハイフンにすると、ファイル名に使いやすくなります。例の領域は不要になったら削除できます。
3. 新しい領域に `index.md`、`rules/approved.md`、`rules/candidates.md`、`knowledge/index.md`、`feedback/index.md`、`sources/index.md` を作ります。例の各ファイルを参考に、空欄から記入してください。実際の資料を例の領域に書き込まないでください。
4. `AGENTS.md` の領域一覧を自分の領域名に更新します。必要なら「資料の閲覧・編集に関する制約」も追記します。`CLAUDE.md` は `AGENTS.md` を参照する入口です。
5. AI に頼むときは、開始時に領域と対象を明示します。例: `scope: [自分の領域名]。対象: [この保管庫内のファイル]。目的: [作業内容]`。対象が複数領域にまたがる場合は、扱うファイルと転記先を個別に指定します。

最初に読むファイルは `AGENTS.md`、[共通手順](Memory/shared/workflow.md)、[記録書式](Memory/shared/formats.md) です。ノート作成には [メモ](Templates/note.md)、[案件](Templates/project.md)、[候補](Templates/candidate.md) を利用できます。テンプレートの角括弧は記入欄です。

## 領域をどう分けるか

領域は、互いの情報を無断で混ぜたくない仕事やテーマごとに作ります。`Memory/scopes/<scope>/` の下に、資料の索引を `sources/`、検証した内容や候補を `knowledge/`、修正経験を `feedback/`、将来の行動指示を `rules/` に置きます。`Memory/shared/` には領域を問わない手順と書式だけを置きます。案件ノートは任意で `Projects/` に作り、どの領域に属するか明記します。

既存ノートを取り込む場合は、対象と領域を先に決め、元ファイルを残したまま参照から始めてください。領域を切り替えるときは新しい会話を始め、前の会話の情報が混入していないか確認します。Markdown の指示だけでアクセスを遮断することはできません。厳密な隔離が必要なら、別の保管庫、OS の権限、利用する AI 側の設定も分けます。

## 知識と承認の違い

`knowledge/` は出典つきの記録です。事実、推測、不確実性を区別します。`feedback/` は予想と実際の差や訂正の記録です。どちらも AI への恒久指示ではありません。繰り返し使う行動規則の案は `rules/candidates.md` に `proposed` として書きます。本人が文言と適用範囲を明示して承認したときだけ `rules/approved.md` に移し、承認日と根拠を記録します。候補の件数や AI の判断だけでは昇格させません。

## AI ツールでの利用

保管庫のルートを作業ディレクトリにして、次のように開始します。

- **Codex**: プロジェクト内の `AGENTS.md` を読む仕組みがあります。開始後、選んだ領域と対象を伝え、最初に読んだ指示を確認してください。[公式説明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **Claude Code**: ルートの `CLAUDE.md` は `@AGENTS.md` で共通入口を取り込みます。起動後に取り込み内容と対象領域を確認してください。[公式説明](https://code.claude.com/docs/en/memory)
- **OpenCode**: ルートの `AGENTS.md` をプロジェクト規則として扱います。参照先ファイルの本文まで自動で読むとは限らないため、開始時に共通手順と書式を読むよう指示してください。[公式説明](https://opencode.ai/docs/rules/)
- **Devin CLI**: ルートの `AGENTS.md` をプロジェクト規則として扱います。共通手順と書式、対象領域の索引を読んだか確認してください。[公式説明](https://docs.devin.ai/cli/extensibility/rules)

これらは各製品の文書に基づく入口の説明です。この配布物で各 CLI の実行や応答への反映は試験していません。製品や設定によって読込範囲が異なります。別アプリの自動記憶、会話履歴、MCP、クラウド上の Knowledge はこの保管庫とは別管理です。このテンプレートはそれらを設定しません。

## 同期と版管理

初めはローカルで使い、同期や Git は必要になってから設定してください。同期前には保存先と共有相手、送信されるファイルを確認します。公開リポジトリには機密資料を入れないでください。Git を使う場合は作業前に `git status` と差分を確認し、他端末の変更を統合してからコミットします。自動 pull、push、デプロイを前提にしません。競合コピーは消さずに内容を照合してください。バックアップと同期は別の用途なので、復元できるバックアップも用意します。

`.gitignore` は代表的なローカル設定や一時ファイルを除外する補助です。過去にコミットした内容は `.gitignore` では消えません。添付ファイル、ログ、秘密情報はコミット前に各自で確認してください。
